# Murad-Farmacy-Rider — «مراد صادق رايدر» (تطبيق الطيار)

تطبيق للطيارين (موقع PWA + APK أندرويد) مربوط بتطبيق العميل Murad-Pharmacy **على نفس شيت الصيدلية** (ورق: الطلبات / الطيارين / الطلبات المكتملة / العملاء).

## إزاي بيشتغل
- العميل يعمل طلب ← يتكتب في ورقة **الطلبات** ← إشعار Firebase يوصل **كل الطيارين الشغالين** ("يعمل" + حالتهم مقبول + عندهم توكن).
- **الأسرع يقبل**: القبول بيتنفذ جوه قفل في السكربت، فلو اتنين دوسوا مع بعض واحد بس بياخد الطلب والتاني تظهرله رسالة.
- بعد القبول **الطيار هو اللي بيحرّك المراحل** بالأزرار: `وصلت الصيدلية — بدء التجهيز` ← `استلمت الطلب — خرجت للتوصيل` ← `تم تسليم الطلب` (بيتأرشف في "الطلبات المكتملة"). كل مرحلة بتظهر للعميل في "مشترياتي" بنفس الأسماء.
- الطيار الجديد يسجّل من التطبيق ← بيظهر في ورقة **الطيارين** بحالة "منتظر" ← أنت تغيّر **حالة الطلب** لـ "مقبول" وهو يدخل لوحده (وبـ "مرفوض" يتقفل عليه).
- **الوصول المتوقع** بيتحسب من GPS الطيار ويتكتب في عمودي "الوصول الي المحل خلال" و"الوصول الي العميل خلال" (يظهر عند العميل). الأول محتاج إحداثيات الصيدلية (خطوة 5)، والتاني محتاج لوكيشن العميل في الشيت (التطبيق الحالي للعميل مش بيبعته، فمش هيظهر إلا لو اتكتب يدوي).
- قبل القبول الطيار بيشوف المنطقة والأصناف والإجمالي بس. الاسم والموبايل والعنوان التفصيلي بيظهروا بعد ما يقبل.
- أقصى عدد طلبات شغالة للطيار الواحد: 3 (`MAX_ACTIVE` في أول `orders.gs`). مينفعش الطيار يوقّف "يعمل" وهو معاه طلب.

## الإعداد (مرة واحدة)

### 1) GitHub
أنشئ مستودع **Public** اسمه `Murad-Farmacy-Rider`، ارفع محتويات المجلد (مع `.github`)، وفعّل **Settings ← Pages ← Source: GitHub Actions**. الموقع هيبقى `https://USERNAME.github.io/Murad-Farmacy-Rider/`.

### 2) سكربت الشيت (مهم: ده بيستبدل سكربت الطلبات القديم)
1. افتح مشروع Apps Script **"اوردارس"** وامسح الكود والصق محتوى `backend/orders.gs` كله (نفس الملف بيخدّم تطبيق العميل والطيار، فاستبدل بيه `backend/orders.gs` في مستودع Murad-Pharmacy كمان).
2. شغّل `setupSheets` مرة (آمنة لو الورق موجود، بتظبط تنسيق الأعمدة).
3. **Deploy ← Manage deployments ← Edit ← Version: New version** (علشان الرابط يفضل نفسه). رابط الويب أب هو `ORDERS_URL` وموجود جاهز في `www/config.js`.
4. افتح الرابط في المتصفح، لازم يظهر `"service":"orders"` ومعاه `version`.

### 3) Firebase (الإشعارات) — **مؤجّل دلوقتي، تخطّاه**
التطبيق والـ APK بيشتغلوا من غير Firebase (التنبيه جوه التطبيق بصوت واهتزاز وهو مفتوح). لما نجهّز Firebase: اتبع الخطوات تحت، وغيّر `PUSH_ENABLED: true` في `www/config.js`، وارفع `google-services.json` (الـ workflow هيركّب الإشعارات لوحده لما يلاقيه).

1. console.firebase.google.com ← **Add project**.
2. **Add app ← Android**: package name `com.muradpharmacy.rider` ← نزّل `google-services.json` وارفعه في **جذر المستودع** (ينفع يتحط على GitHub، مفيهوش أسرار).
3. **Add app ← Web**: انسخ القيم (`apiKey`, `authDomain`, `projectId`, `messagingSenderId`, `appId`) في `FIREBASE` جوه `www/config.js`. من **Project settings ← Cloud Messaging ← Web Push certificates ← Generate key pair** انسخ المفتاح في `vapidKey`. (لو مش عايز إشعارات المتصفح سيب `FIREBASE` فاضي، والـ APK هيشتغل عادي.)
4. **Project settings ← Service accounts ← Generate new private key**. من الملف اللي نزل (**ممنوع يترفع على GitHub**) حط في Apps Script (**Project Settings ← Script properties**):
   - `FIREBASE_PROJECT_ID` = `project_id`
   - `FIREBASE_CLIENT_EMAIL` = `client_email`
   - `FIREBASE_PRIVATE_KEY` = `private_key` (كامل بـ BEGIN/END)
   - `RIDER_WEB_URL` = رابط الموقع من خطوة 1 (بيفتحه لما الطيار يدوس على إشعار المتصفح)
5. في المحرر شغّل `testFirebase` (لازم يطلع ✅ في Execution log). بعد ما طيار يفعّل الإشعارات شغّل `testPushToAllRiders` لتجربة إشعار.

### 4) APK
**Actions ← Build Android APK ← Run workflow**، وبعد ~5 دقايق نزّل `murad-rider-apk` من Artifacts. التحديثات بتتثبت فوق القديمة لأن المفتاح ثابت (`debug.keystore`). الإشعارات في الـ APK بتشتغل والتطبيق مقفول.

### 5) إعدادات `www/config.js`
- `SUPPORT_PHONE`: رقم الإدارة اللي بيظهر في «المساعدة والدعم» (اتصال/واتساب).
- `STORE`: إحداثيات الصيدلية.

### 5-أ) إحداثيات الصيدلية
في `www/config.js` حط `STORE: { lat: ..., lng: ..., mapUrl: "" }` (اضغط مطولاً على موقع الصيدلية في خرائط جوجل وانسخ الرقمين). من غيرها الوصول المتوقع للصيدلية مش بيظهر.

## شكل التطبيق
- تبويبات تحت: **الطلبات الجديدة / المقبولة / التوصيل / تم التوصيل**. زرار «يعمل الآن / لا يعمل» تحت الهيدر، والقائمة (3 شرطات) فيها: الصفحة الشخصية، الأرباح، المحفظة، البريد الوارد، المساعدة والدعم، حول.
- الفاتورة مخفية افتراضياً (زرار «الطلب» ← «إخفاء الفاتورة») وفيها سطر «التوصيل» بصفر لحد ما نحدد طريقة حسابه (`DELIVERY_FEE` في `www/assets/app.js`).
- المراحل: تم القبول ← «وصلت الصيدلية» (جاري التجهيز، ينتقل لتبويب التوصيل) ← «تم تجهيز الطلب — توصيل الطلب» ← «تم توصيل الطلب».

## الأرباح وسعر التوصيل
- سعر التوصيل بيتحدد في أول `orders.gs` (`DELIVERY_FEE`، حاليًا 0). بيظهر كسطر «التوصيل» في الفاتورة وبيتحسب كربح للطيار، فلما تحدد القيمة غيّرها هناك وبس.
- «الأرباح» في القائمة: ملخص الوردية + «سجل الأرباح الكامل» (أسبوعي، تفاصيل اليوم والطلب، تقويم لفترة مخصصة، حذف أيام) + «إنهاء حساب الطيار» (بيصفّر ويمسح قائمة «تم التوصيل» ويسيب السجل).
- سجل الأرباح محفوظ على جهاز الطيار، وبيتكمّل من آخر طلبات اتسلّمت على السيرفر.

## ملاحظات
- كلمة مرور الطيار بتتخزن في الشيت كنص عادي (علشان تقدر تشوفها وتغيّرها). سيب ورقة الطيارين خاصة بيك ومتشاركهاش.
- لحد ما نفعّل Firebase، الطيار لازم يسيب التطبيق مفتوح علشان يوصله تنبيه الطلب الجديد.
- الإشعارات للعميل (Push) مش في النسخة دي، العميل بيشوف التحديثات في "مشترياتي" بالسحب الدوري.
- مش موجود في النسخة الأولى: الأيقونة العائمة، التتبع في الخلفية، شات الطيار/العميل، الدعم الفني، الأرباح الأسبوعية. ينفع نضيفهم بعد ما الأساس يستقر.
- لو الطيار فتح التطبيق على جهازين، الإشعارات بتروح لآخر جهاز سجّل (توكن واحد لكل طيار).
